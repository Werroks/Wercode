# Architecture: Wercode (рабочее имя) — терминал + файлы + git + редактор



## Stack

| слой | выбор | почему |
| --- | --- | --- |
| язык | Rust, edition 2024, stable | требование пользователя |
| UI-фреймворк | `gpui` (Zed) | нативный GPU-рендер; Windows боевой с Zed 1.0 |
| UI-компоненты | `gpui-component` 0.9.x (GPUI Kit, Apache-2.0) | в нём уже есть Dock, Resizable, Tabs, Tree, Editor, Diff, Command, Settings, Theme, Menu, TitleBar, VirtualList — почти весь наш интерфейс |
| эмуляция терминала | `alacritty_terminal` (Apache-2.0) | аналог xterm.js; сетка, scrollback, выделение, режимы мыши |
| PTY | `portable-pty` (MIT) | аналог node-pty; ConPTY на Windows |
| виджет терминала | свой, поверх `alacritty_terminal` | `gpui-terminal` 0.1.0 не умеет выделение мышью и прокрутку истории — берём его только как пример устройства |
| редактор | `Editor` из gpui-component | подсветка tree-sitter, gutter, folding; заявлена работа на 200 тыс. строк |
| git | системный `git` через `std::process` (`status --porcelain=v2 -z`, `diff`, `add`, `commit`, `push`) | так же делает VS Code; авторизация, хуки и конфиг работают как у пользователя; ноль лишних зависимостей. `gix` — только если status окажется медленным |
| дерево файлов | `ignore` (обход с .gitignore) + `notify-debouncer-full` (слежение) | библиотеки из ripgrep |
| поиск по проекту | `grep-searcher` + `grep-regex` + `ignore` | движок ripgrep как библиотека, потоковая выдача |
| нечёткий поиск | `nucleo` | палитра и быстрое открытие файла |
| конфиг и состояние | `serde` + `toml` (настройки, темы), `serde_json` (состояние) | — |
| пути | `directories` | правильные каталоги на трёх ОС |
| ошибки и логи | `anyhow`, `tracing` | — |
| лицензия проекта | MIT OR Apache-2.0 | совместима со всеми зависимостями |
| сборка и релизы | GitHub Actions: Windows, macOS, Linux; `cargo-dist` | бинарники в Releases |

Версии крейтов не фиксирую здесь: `gpui-component` сам тянет подходящий `gpui`, остальное берём последнее на момент `cargo add`.

Чего в стеке нет намеренно: webview, Node, база данных, сеть, аккаунты, телеметрия.

## Структура проекта

Один репозиторий, один cargo workspace, два крейта. Граница простая: `core` не знает про окно и тестируется без GPU.

```
wercode/
  Cargo.toml                 workspace
  crates/
    core/                    без UI
      src/
        config.rs            Settings: чтение, запись, значения по умолчанию
        state.rs             Workspace state, недавние проекты
        theme.rs             формат темы, встроенные темы
        shell.rs             поиск шеллов в системе
        pty.rs               запуск шелла, чтение/запись, resize, завершение
        fs_tree.rs           ленивое дерево, .gitignore, слежение
        git.rs               вызовы git, разбор porcelain v2 и diff
        search.rs            поиск по проекту, потоковые результаты
        fuzzy.rs             индекс файлов для быстрого открытия
    app/                     бинарник `wercode`
      src/
        main.rs              разбор аргументов, запуск окна
        actions.rs           все команды и горячие клавиши
        workspace.rs         корневой вид: титул, центр, правая панель
        titlebar.rs          имя проекта, список недавних
        center/              вкладки и сплиты (терминалы и редакторы вместе)
        term/                view.rs, input.rs, links.rs, osc.rs, tabs.rs
        editor/              обёртка над Editor: открыть, сохранить, перечитать
        panel/               files.rs, git.rs, search.rs, settings.rs
        palette.rs           команды и быстрое открытие файла
        welcome.rs
  assets/
    themes/*.toml            встроенные цветовые схемы
    icons/*.svg              свои иконки
```

### Потоки и данные

- На каждый терминал — отдельный поток чтения PTY. Он кормит парсер `alacritty_terminal` и шлёт в UI сигнал «перерисуй»; сигналы склеиваются до одного на кадр. Без этого большой вывод вешает интерфейс.
- Git, поиск, обход дерева, чтение файлов — в фоновом исполнителе GPUI. UI-поток никогда не трогает диск и не ждёт процессов.
- Слежение за файлами: одно на проект, события склеиваются за ~150 мс и раздаются дереву, git-панели и открытым редакторам.
- Git-статус пересчитывается по событию файловой системы и по фокусу окна, не чаще раза в ~300 мс; новый запрос отменяет старый.

## Schema (файлы на диске)

Файлов: 3 вида. Каталоги — через `directories` (Windows: `%APPDATA%\wercode\`, Linux: `~/.config/wercode/`, macOS: `~/Library/Application Support/wercode/`).

```toml
# settings.toml — правит пользователь или экран настроек; применяется сразу
theme = "black"                  # имя темы
font_family = "Cascadia Mono"
font_size = 14
line_height = 1.2
shell = "auto"                   # или путь / имя профиля
shell_args = []
scrollback = 10000
cursor_style = "block"           # block | bar | underline
cursor_blink = true
copy_on_select = false
panel_side = "right"             # right | left
confirm_close_running = true
editor_tab_size = 4
editor_word_wrap = false
editor_autosave = "off"          # off | on_focus_loss

[keys]                           # только переопределения
"ctrl-shift-t" = "terminal::NewTab"
```

```jsonc
// state.json — пишет только приложение
{
  "version": 1,
  "recent": [{ "path": "C:/code/app", "opened_at": "2026-11-11T10:00:00Z" }],
  "workspaces": {
    "C:/code/app": {
      "panel_visible": true,
      "panel_width": 320,
      "active_panel": "files",          // files | git | search | settings
      "expanded_dirs": ["src", "src/ui"],
      "layout": { /* дерево сплитов и вкладок; терминал: cwd, shell; редактор: path */ },
      "window": { "x": 0, "y": 0, "w": 1400, "h": 900, "maximized": false }
    }
  }
}
```

```toml
# themes/<name>.toml — встроенные лежат в бинарнике, пользовательские в каталоге конфига
name = "Black"
appearance = "dark"

[ui]
background = "#000000"
surface = "#0b0b0b"
border = "#1f1f1f"
text = "#e6e6e6"
text_muted = "#8a8a8a"
accent = "#4c9aff"
# + selection, hover, danger, added, modified, deleted

[terminal]
foreground = "#e6e6e6"
background = "#000000"
cursor = "#e6e6e6"
ansi = ["#000000", "..."]         # 16 цветов

[syntax]
keyword = "#c792ea"
string = "#c3e88d"
# comment, function, type, number, constant, ...
```

Правила:
- Битый `settings.toml` не роняет запуск: работаем на значениях по умолчанию и показываем уведомление с номером строки.
- `state.json` пишется атомарно (временный файл, затем переименование), с задержкой ~1 с после изменения. Незнакомая `version` — файл игнорируется, не удаляется.
- Содержимое вывода терминалов не сохраняется; восстанавливаются только вкладки, сплиты и их cwd.
- Несохранённый текст редактора при выходе: спросить (сохранить / не сохранять / отмена). Тихого сохранения нет.

Фоновые задачи: слежение за файлами (постоянно), пересчёт git-статуса (по событиям), индекс имён файлов для Ctrl+P (при открытии проекта и по событиям), отложенная запись `state.json`.

Сеть: приложение само никуда не ходит. В сеть ходит только `git`, запущенный пользователем через кнопки Push/Pull/Fetch.

## The parts that bite

- **ConPTY (Windows):** ресайз во время вывода портит экран — ресайз с задержкой и только при реальном изменении числа строк/колонок. Старые сборки Windows 10 дают артефакты; минимальная версия — Windows 10 1809, проверить на реальной машине.
- **Клавиши терминал против приложения:** Ctrl+C, Ctrl+V, Ctrl+W, Ctrl+P нужны программам в терминале. Когда фокус в терминале, приложение перехватывает только сочетания с Ctrl+Shift и Alt; всё остальное уходит в шелл. Поэтому Ctrl+P / Ctrl+W / Ctrl+S работают только при фокусе в редакторе или панели, а палитра из терминала — Ctrl+Shift+P.
- **Ввод:** IME, мёртвые клавиши, AltGr, русская раскладка — проверять отдельно; здесь ломаются почти все самодельные терминалы.
- **Шрифты:** ширина ячейки, эмодзи и CJK двойной ширины, fallback-шрифты, лигатуры (по умолчанию выключены).
- **Большой вывод:** чтение PTY не должно блокироваться отрисовкой; перерисовка не чаще кадра.
- **Гонки с диском:** агент в терминале меняет файл, открытый в редакторе. Правило: если в редакторе нет несохранённых правок — молча перечитать; если есть — показать полосу «файл изменён на диске» с выбором «перечитать / оставить моё». При сохранении сверять время изменения файла.
- **Гонки git:** `index.lock` от параллельной команды пользователя в терминале — повторить через паузу, не показывать ошибку с первого раза. Каждый новый пересчёт статуса отменяет предыдущий.
- **Большие репозитории:** дерево только лениво; слежение уважает .gitignore (иначе `node_modules` и `target` съедят лимиты наблюдателя, особенно на Linux — inotify); Ctrl+P индексирует только неигнорируемые файлы.
- **Большие и бинарные файлы:** файл больше ~20 МБ или с нулевыми байтами не открывается в редакторе, показывается заглушка.
- **Кодировки и переводы строк:** читаем UTF-8 (с BOM и без), сохраняем как было; CRLF/LF определяем при открытии и не меняем.
- **Пути Windows:** длинные пути, UNC, регистр, WSL-пути (`\\wsl$\...`) — git и слежение там ведут себя иначе; WSL-проекты вне MVP.
- **Удаление:** только в корзину (`trash`), никогда безвозвратно.
- **Завершение:** при закрытии окна убить дерево процессов каждого шелла (на Windows — через Job Object), иначе остаются сироты.
- **GPUI:** документации мало, API меняется между версиями — фиксировать версии в `Cargo.lock`, обновлять осознанно.
- **Лицензии:** в код не попадает ничего из Zed (GPL-3) и из других редакторов; иконки и палитры свои.

## Build order

Первой целевой ОС беру Windows (на ней идёт разработка), затем Linux и macOS.

0. **Подготовка.** Установить Rust (rustup + MSVC Build Tools) — сейчас на машине нет `rustc` и `cargo`. `git init`, workspace из двух крейтов, CI на сборку. Проверка стека: окно `gpui-component` с тёмной темой запускается на Windows.
1. **Вертикальный срез** (W01, F01, F04 частично). `wercode .` открывает окно, в центре один рабочий терминал: ввод, цвета, ресайз, прокрутка, выделение, копирование/вставка. Справа — дерево файлов только для чтения. Это доказывает самую рискованную часть.
2. **Терминал целиком.** Вкладки, сплиты в обе стороны, выбор шелла, закрытие с подтверждением, ссылки и пути, отслеживание cwd, поведение по таблице VS Code.
3. **Оболочка.** Титул с именем проекта и списком недавних, три кнопки, сворачиваемая панель со сплиттером, экран приветствия, палитра команд, сохранение и восстановление состояния (W05, W07, F06).
4. **Файлы и редактор.** Живое дерево с .gitignore и git-метками, контекстное меню, вставка пути в терминал; редактор во вкладках: открыть, править, сохранить, поиск/замена, перечитывание при изменении на диске; Ctrl+P (W02, W06, F02).
5. **Git.** Статус, stage/unstage, commit, ветка и ahead/behind, diff во вкладке; затем push/pull/fetch, ветки, discard (W03, F03).
6. **Поиск и настройки.** Панель поиска по проекту; экран настроек; 4–5 встроенных цветовых схем; переопределение клавиш (W04, F05).
7. **Выпуск.** Сборки под три ОС, иконка, README, лицензия, релиз на GitHub.
8. **Should и could** из `features.csv`: пословный diff, история коммитов, stage по кускам, worktrees, свои темы из файла, панель слева, несколько окон, превью картинок, LSP по желанию.

После шага 1 стоит остановиться и честно оценить: если терминал на GPUI под Windows ощущается плохо, запасной путь — Tauri 2 + xterm.js; крейт `core` при этом сохраняется целиком.
