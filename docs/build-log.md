## Git: diff, discard, push/pull/fetch, ветки (2026-11-13): что сделано

- Клик по файлу в git-панели открывает вкладку с его изменениями (компонент Diff библиотеки): единый столбец, подсветка синтаксиса, отдельно для «Changes» и «Staged Changes». Вкладка перечитывается при изменениях на диске и в репозитории и не сохраняется между запусками. Сам файл открывает кнопка в строке.
- Кнопка Discard у каждой строки «Changes»: после вопроса возвращает файл к тексту из индекса; новый файл, которого git ещё не знает, уходит в корзину.
- Fetch, Pull, Push над полем сообщения, с числом коммитов. Первый push ветки публикует её в `origin`. Ошибка git показывается под полем. Пароль git не спрашивает: доступ должен уже работать в терминале.
- Ветки: клик по ветке в строке состояния или «Git: Switch or Create Branch» в палитре открывает список локальных веток и поле для новой. Если git отказывает (переключение затёрло бы правки), его слова остаются в списке.

Проверено автотестами (`cargo test`: 38 в ядре, 28 в приложении): патчи для изменённого, staged и нового файла, discard, ветки, push/fetch/pull в соседний bare-репозиторий; в окне без экрана — клик по файлу открывает вкладку с верным числом строк, повторный клик не плодит вкладки, Discard с отменой и с подтверждением, первый push, создание и переключение ветки, отказ на занятое имя.

Проверено в настоящем окне (Windows 11): вкладка diff с подсветкой, кнопки в панели, список веток.

Не проверено руками: Discard, Push, Pull, Fetch и переключение ветки в настоящем окне (только автотест); diff staged-файла, удалённого файла и бинарного файла; push с запросом пароля.

## Быстрое открытие файла, свои сочетания клавиш, перетаскивание пути (2026-11-13): что сделано

- Быстрое открытие файла: Ctrl+Shift+K или «File: Go to File…» в палитре (простой Ctrl+P оставлен шеллу — там это «предыдущая команда»). Буквы ищутся по порядку; совпадение в имени файла весит больше, чем в папках; заглавные буквы и начала слов дают прибавку; можно писать `core/watch`. Игнорируемые файлы не показываются. Список файлов читается в фоне (`core::finder`), показываются 50 лучших.
- Свои сочетания клавиш: таблица `[keys]` в `settings.toml`, например `"terminal.new_tab" = "ctrl-shift-y"` (можно `Ctrl+Shift+Y`, можно список). Пустое значение убирает сочетание. Все встроенные сочетания теперь заданы в одном месте, `crates/app/src/keymap.rs`. Экран настроек показывает имена команд с текущими сочетаниями и пишет, что из `[keys]` не удалось разобрать. Изменения в файле подхватываются при открытии экрана настроек.
- Файл или папку из дерева можно перетащить на терминал — путь печатается так же, как по Alt+клику. Файлы, перетащенные из другой программы (Проводник), печатаются тоже.
- Подпись «Ctrl+Shift+N» в меню проекта берётся из действующих сочетаний, а не написана в коде.

Проверено автотестами (`cargo test`: 40 в ядре, 33 в приложении): оценка совпадений и обход папки без игнорируемых файлов; таблица `[keys]` читается и переживает сохранение других настроек; в окне без экрана — открытие файла по трём буквам, замена сочетания, пустое значение, нечитаемое сочетание и несуществующая команда, возврат встроенного сочетания, перетаскивание строки дерева на терминал.

Проверено в настоящем окне (Windows 11): «Go to File» из палитры, ввод `keymap` нашёл и открыл `keymap.rs`; `Cargo.toml`, перетащенный из дерева, появился в строке PowerShell; список сочетаний на экране настроек.

Не проверено руками: само нажатие Ctrl+Shift+K и изменённых сочетаний в настоящем окне (помощник `drive.ps1` не умеет нажимать клавиши с Ctrl и Shift — только автотест); перетаскивание файла из Проводника; очень большой проект в быстром открытии.

## Терминал под кодом (2026-11-13): что сделано

- В настройках появился пункт «Layout»: «One row of tabs» (как было: файлы и терминалы — вкладки одного ряда) или «Terminal below files» (как в Cursor и VS Code: файлы сверху со своими вкладками, терминалы снизу со своими). В `settings.toml` это `layout = "tabs"` или `"terminal_below"`. Переключается сразу, вкладки и шеллы остаются теми же.
- В режиме «терминал снизу»: границу между кодом и терминалом можно тянуть; Ctrl+Shift+J (`terminal.toggle`, «Terminal: Show or Hide» в палитре) переводит клавиатуру в терминал, а из терминала прячет его; то же делают кнопки справа в рядах вкладок. Пока ни один файл не открыт, терминал занимает всё место. Ctrl+Tab ходит по вкладкам того ряда, где клавиатура. Сплит, запрошенный из файла, делается в терминале снизу. Закрытый файл уступает место другому файлу, закрытый терминал — другому терминалу; если терминалов не осталось, панель исчезает до следующего Ctrl+Shift+J или Ctrl+Shift+T.
- Высота панели и то, что она спрятана, запоминаются для каждого проекта.
- В режиме одного ряда Ctrl+Shift+J переходит на вкладку терминала, которая была открыта последней.

Проверено автотестами (`cargo test`: 40 в ядре, 34 в приложении): в окне без экрана — без файлов виден только терминал; с файлами видны обе части; Ctrl+Tab остаётся в своём ряду; сплит из файла; прятать и возвращать панель; закрытие файлов; возврат к одному ряду.

Проверено в настоящем окне (Windows 11): переключатель в настройках, код сверху и PowerShell снизу, вкладки разошлись по своим рядам.

Не проверено руками: перетаскивание границы, кнопки «спрятать» и «показать», Ctrl+Shift+J — в это время окном пользовался сам пользователь, и посланные помощником нажатия смешались с его; восстановление высоты панели после перезапуска.

## Крестик у каждого терминала (2026-11-13): что сделано

- Когда во вкладке несколько терминалов, у каждого в правом верхнем углу свой крестик: он закрывает именно этот терминал, а не тот, где сейчас клавиатура. Если в терминале работает программа, вопрос задаётся как обычно. У единственного терминала крестика нет — его закрывает крестик вкладки.

Проверено автотестом: крестик неактивного терминала закрывает его, активный остаётся. Проверено в настоящем окне (Windows 11): после сплита крестики видны у обоих терминалов, клик по крестику оставил один терминал.

## Чистое окружение для шеллов и сочетания клавиш для git (2026-11-14): что сделано

- Claude Code в терминале Wercode писал «Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker» и был чёрно-белым. Причина: Wercode запускали из Claude Code (`cargo run` через его PowerShell), а тот ставит своим командам `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION` и подобные, плюс `NO_COLOR=1`, `GIT_EDITOR=true` и `GIT_TERMINAL_PROMPT=0`. Wercode передавал всё это своим шеллам, и вложенный `claude` считал себя дочерней сессией без цвета. Теперь первой строкой `main` (`core::environment`) метки Claude Code убираются всегда, а `NO_COLOR` и настройки git — только если рядом есть эти метки: иначе это выбор самого пользователя. Заодно убирается канал паролей git от терминала VS Code или Cursor (`GIT_ASKPASS`, `VSCODE_GIT_*`): он закрывается вместе с редактором. `TERM_PROGRAM_VERSION` теперь версия Wercode, а не редактора.
- Сочетания для git (в `keymap.rs`, меняются через `[keys]`): Ctrl+Shift+↑ — push (`git.push`), Ctrl+Shift+↓ — pull (`git.pull`), Ctrl+Shift+R — fetch (`git.fetch`), Ctrl+Shift+Enter — коммит (`git.commit`): с сообщением в git-панели коммитит, без него открывает панель и ставит курсор в поле. Stage All (`git.stage_all`) — в палитре, без сочетания. В палитре добавлены «Git: Pull / Push / Fetch / Commit / Stage All Changes».
- Пока идёт fetch, pull или push, строка состояния пишет «Fetching… / Pulling… / Pushing…»; неудача остаётся там красным («Push failed») до следующей команды, клик открывает git-панель со словами git.

Проверено автотестами (`cargo test`: 44 в ядре, 35 в приложении): какие переменные убираются при запуске из Claude Code, из терминала Cursor и при обычном запуске; в окне без экрана — Ctrl+Shift+Enter без сообщения открывает панель с курсором в поле, с сообщением коммитит; Ctrl+Shift+↑ публикует ветку, ↓ и R проходят без ошибки; ошибка fetch видна в строке состояния при скрытой панели и по клику открывает панель; Stage All из палитры.

Проверено в настоящем окне (Windows 11): Wercode, запущенный из PowerShell-инструмента Claude Code, — в его терминале `set claude`, `set ai`, `set git` пусто, `NO_COLOR` нет, `TERM_PROGRAM=wercode`, `COLORTERM=truecolor`.

Не проверено руками: сам `claude` в терминале Wercode после исправления (цвет и отсутствие предупреждения — по переменным, а не глазами); нажатия новых сочетаний в настоящем окне (`drive.ps1` не умеет Ctrl+Shift); push с запросом пароля.


## Выпуски, автообновление и история коммитов (2026-11-14): что сделано

- Выпуск по тегу `v*` (`.github/workflows/release.yml`). Windows: установщик Inno Setup для одного пользователя, без прав администратора, в `%LOCALAPPDATA%\Programs\Wercode`; ярлык в «Пуске», по желанию на рабочем столе, пункт «Открыть в Wercode» в меню папок; языки установщика: английский, русский, немецкий, испанский. macOS: универсальный `Wercode.app` (Apple silicon и Intel, ad-hoc подпись), `.dmg` для людей и `.tar.gz` для обновлений. Linux: `.tar.gz` с программой, значком, ярлыком меню и `install.sh` (ставит в `~/.local/bin`). Плюс `latest.json` и `SHA256SUMS.txt`. Ручной запуск workflow собирает всё без выпуска — для пробы.
- Автообновление (`core::update`, `app::update`): раз в 4 часа (первый раз через 15 с после старта) читается `latest.json` последнего выпуска через системный `curl`; новая версия скачивается в фоне, проверяется SHA-256 и ставится при выходе из Wercode. «Restart to update to X» в строке состояния закрывает окна обычным порядком (с вопросами о несохранённом и запущенном) и запускает новую версию; отказ в любом окне отменяет перезапуск. В настройках: переключатель «Automatic updates», «Check Now», состояние. В палитре: «Help: Check for Updates». Сборки из исходников (без `WERCODE_RELEASE`) не обновляются. На Windows приложение держит мьютекс `WercodeRunning`, установщик ждёт его исчезновения.
- История коммитов: секция GRAPH под изменениями в git-панели, граница перетаскивается, секция сворачивается. Дорожки и точки разных цветов, у текущего коммита кольцо, у слияний полая точка; метки веток, удалённых веток и тегов; автор; при наведении — карточка с хешем, автором и временем. Клик по коммиту раскрывает его файлы (дорожки продолжаются вдоль них), клик по файлу открывает вкладку с тем, что коммит в нём изменил. Показывается текущая ветка и та, за которой она следит; 200 коммитов и «Show More Commits». История перечитывается, когда меняются HEAD, ветка или счётчики ahead/behind.

Проверено автотестами (`cargo test`: 57 в ядре, 36 в приложении): сравнение версий, разбор `latest.json`, проверка SHA-256, распаковка и подмена исполняемого файла и `Wercode.app`; разбор `git log` с ветками и тегами, раскладка дорожек для прямой истории, слияния и двух вершин, файлы коммита с переименованиями, время «сколько назад»; в окне без экрана — история с веткой и слиянием (две дорожки), раскрытие коммита, вкладка изменений коммита, новый коммит появляется сам, сворачивание.

Проверено в GitHub Actions: пробная сборка выпуска прошла на Windows, macOS и Linux; содержимое архивов совпадает с тем, что ждёт обновление. Проверено в настоящем окне (Windows 11): граф на истории самого Wercode, раскрытие коммита.

Не проверено руками: установка и обновление на macOS и Linux (там их никто не запускал); `.dmg` на настоящем Mac.


## Языки интерфейса, поиск в терминале, вкладки и выбор оболочки (2026-11-14): что сделано

- Языки: английский, русский, немецкий, испанский, китайский. В настройках пункт «Language» — «Автоматически» (язык компьютера) и пять языков, каждый своим названием. Меняется сразу, вместе с подсказками в полях. Все тексты идут через `core::i18n` (`t`, `tf`, `tn`), переводы — в `crates/core/locales/*.toml`, ключ — английский текст. Числа склоняются по правилам языка (в русском три формы). Тест находит в коде каждый текст и падает, если где-то нет перевода, есть лишний или не совпадают `{подстановки}`. Сообщения ядра (ошибки git, файлов, обновления) тоже переведены. Тексты библиотеки компонентов переключаются, где у неё есть язык (русский, китайский).

Поле справа сверху, ищется от самого нового вывода; Enter и стрелка вверх — к более старым совпадениям, стрелка вниз — к новым; найденное выделяется и прокручивается в вид. Строчные буквы ищут без учёта регистра, заглавная включает учёт. Поле стоит рядом с терминалом, а не в нём, поэтому набранное в поиске не попадает в шелл.
- Вкладки: двойной клик по вкладке терминала (или «Терминал: переименовать вкладку…») — своё имя; Enter сохраняет, пустое имя возвращает автоматическое, Esc отменяет; имя запоминается до следующего запуска. Вкладки перетаскиваются мышью на новое место.

Проверено автотестами (`cargo test`: 61 в ядре, 37 в приложении): правила чисел, разбор кодов языков, полнота переводов на четыре языка; поиск в выводе настоящего шелла (с учётом регистра и без); в окне без экрана — переименование через палитру и сохранение имени в раскладке, терминал с выбранной оболочкой и её сплит, перестановка вкладок с сохранением активной, открытие и закрытие поля поиска.

## Проверка кода языковыми серверами, README и лицензии (2026-11-15): что сделано

- Линтер: Wercode находит установленные языковые серверы (на `PATH` и в обычных папках установки: `~/.cargo/bin`, `%APPDATA%\npm`, `/opt/homebrew/bin` и т. п.) и запускает их на проект, когда открыт файл их языка: rust-analyzer, typescript-language-server, basedpyright/pyright/pylsp и рядом ruff, gopls, clangd, серверы JSON/CSS/HTML из vscode-langservers-extracted, yaml-language-server, bash-language-server, taplo, ruby-lsp. Протокол — свой небольшой клиент в `core::lsp` (поток на сервер, JSON-RPC по stdin/stdout, полный текст при каждом изменении, колонки пересчитываются из UTF-16 в символы).
- В редакторе ошибки и предупреждения подчёркиваются волнистой линией, сообщение — при наведении. Текст уходит серверам через 300 мс после паузы в наборе; компонент редактора стирает подчёркивания на каждое нажатие, поэтому после паузы старые возвращаются до ответа сервера.
- Строка состояния: счётчики ошибок и предупреждений проекта (клик открывает список) и состояние сервера открытого файла: «запуск», работа с процентами (например, индексация rust-analyzer), имя готового сервера. Нет сервера — «Нет языкового сервера для Python» и кнопка «Установить»: команда запускается во вкладке терминала, а Wercode каждые 10 с ищет сервер снова и сам его запускает. ## Замена по проекту, ветки с сервера и удаление ветки (2026-11-16)

- Замена по проекту: в панели поиска второе поле «Заменить на» и кнопка «Заменить все». Сначала вопрос («Заменить 4 совпадения в 2 файлах?»), затем каждое совпадение в найденных файлах заменяется на диске (`core::search::replace`): кодировка и концы строк файла сохраняются, в регулярном выражении работают `$1` и `${name}`, в обычном тексте `$` — просто знак. Открытые файлы без несохранённых правок перечитываются сами, с правками — показывают полосу «изменён на диске». Отмены нет — для неё git.
- Ветки: в списке веток после локальных идут те, что есть только на сервере (`origin/имя`), клик создаёт локальную ветку, следящую за ней (`git switch --track`). У локальных веток, кроме текущей, крестик — удаление через `git branch -d`: ветку с коммитами, которых больше нигде нет, git не удалит, и его слова останутся в списке.

Проверено автотестами (`cargo test`: 73 в ядре, 41 в приложении): замена в файлах с LF и CRLF, группы регулярного выражения, пропавший файл; список веток сервера, слежение, отказ удалить текущую ветку; в окне без экрана — «Заменить все» с вопросом и итоговой строкой, удаление ветки и возврат её с сервера.

Проверено в настоящем окне (Windows 11, релизная сборка): вид панели поиска с полем замены, список веток с крестиками, удаление ветки `spare`.

## Полоски изменений в редакторе (2026-11-16)

- Слева от номеров строк — полоска: зелёная у новых строк, жёлтая у изменённых, красная отметка там, где строки удалены. Сравнение идёт с последним коммитом (`git show HEAD:./файл`, `core::git::committed_text`), а не с диском, поэтому несохранённые правки тоже отмечены. Пересчёт — через 300 мс после паузы в наборе, после сохранения и перечитывания файла, и когда у репозитория сменился HEAD или ветка.
- Сравнение строк своё (`core::linediff`): одинаковые начало и конец файла отбрасываются, середина сравнивается по наибольшей общей последовательности строк; если середина огромная (больше 4 млн пар строк), она считается изменённой целиком. Концы строк CRLF и LF не считаются отличием.
- Полоски рисует сам компонент редактора (`GutterDecoration`); он же держит их на своих строках между пересчётами.
- Заодно: список скриптов `package.json` теперь всегда отсортирован по имени. `serde_json` в одних сборках хранит порядок файла, в других сортирует (зависит от того, какие возможности включили соседние библиотеки), и тест ядра вёл себя по-разному при `cargo test` и `cargo test -p wercode-core`.

Проверено автотестами (`cargo test`: 76 в ядре, 43 в приложении): добавленные, изменённые и удалённые строки в разных сочетаниях, текст файла из коммита; в окне без экрана — отметки у открытого файла настоящего репозитория и их сдвиг после правки.

Проверено в настоящем окне (Windows 11, релизная сборка): зелёные и жёлтые полоски у `main.rs` демо-проекта совпадают с `git diff`.

Не сделано: inline blame (кто и когда менял строку) — вторая половина пункта плана. Не проверено руками: красная отметка удаления, смена ветки при открытом файле.

## Кто менял строку (2026-11-16)

- Строка состояния показывает, кто и когда последним менял строку под курсором и в каком коммите: «автор, 3 дня назад · первая строка сообщения». Вопрос уходит git через 300 мс после остановки курсора (`git blame --porcelain -L n,n`, `core::git::blame_line`). Для строки, которой ещё нет в коммите, и пока в файле есть несохранённые правки (git знает файл на диске, а строки уже могли сдвинуться), ничего не показывается.

- Окно теперь перерисовывает строку состояния при каждом изменении в центральной области (раньше — только когда менялась раскладка вкладок).

Проверено автотестами (`cargo test`: 77 в ядре, 43 в приложении): разбор ответа `git blame`, строка из коммита и незакоммиченная строка в настоящем репозитории; в окне без экрана — автор и сообщение для строки под курсором, пусто для новой строки.

Проверено в настоящем окне (Windows 11, релизная сборка): «demo, 9 hours ago · Forecast for a city» для строки `forecast.rs`.

## Перенос строки, скриншоты в терминал, видимая подсветка строк (2026-11-17)

- Ctrl+Enter и Shift+Enter в терминале отправляют перевод строки (`\n`), как консоль Windows для Ctrl+Enter. Claude Code начинает по нему новую строку, а не отправляет набранное; оболочка по-прежнему выполняет команду; PowerShell читает это как Ctrl+Enter («новая строка выше»). Alt+Enter, как и раньше, — Esc и Enter.
- Вставка (Ctrl+V в Windows, Ctrl+Shift+V, Shift+Insert, правая кнопка) теперь понимает не только текст. Картинка из буфера (скриншот Win+Shift+S, «Копировать картинку» в браузере) сохраняется в `%TEMP%\wercode-pasted\image-<время>.png` (`core::pasted`; bitmap и TIFF переводятся в PNG, PNG/JPEG/GIF/WebP остаются как есть), и в терминал вставляется её путь. Claude Code, получив вставкой путь к картинке, прикладывает её как `[Image #1]` (проверено по коду Claude Code: он обрезает пробелы, снимает кавычки и читает файл с расширением png/jpg/gif/webp). Пробел после пути набирается отдельно, чтобы вставка была ровно путём. Картинки старше недели удаляются при следующей вставке. Файлы, скопированные в проводнике, вставляются путями.
- Строка под указателем и выбранная строка в меню и всплывающих окнах не были видны: цвет наведения (`list_hover`) и выбора (`accent`, `list_active`) совпадал с фоном всплывающего окна (`popover`), оба `surface_2`. Так было в списке недавних проектов, в палитре команд, в меню. Теперь оба цвета вычисляются из темы (`Ui::hover`, `Ui::chosen`): на шаг от `surface_2` к цвету текста, так что видны и на боковой панели, и во всплывающих окнах, в светлой теме тоже.

Проверено автотестами (`cargo test`: 80 в ядре, 45 в приложении): сохранение картинки (PNG как есть, bitmap → PNG, мусор — ошибка, старые файлы удаляются, чужие нет), различимость наведения и выбора во всех встроенных темах, коды Ctrl/Shift+Enter; в окне без экрана — bitmap в буфере, Ctrl+Shift+V, на экране путь к PNG.

Не проверено руками: Ctrl+Enter и вставка скриншота в настоящем окне с запущенным Claude Code; подсветка в настоящем окне.

## Поле для запроса агенту, новое окно на виду, поддержка проекта (2026-11-19)

- Поле для запроса (prompt box) — как поле ввода в панелях Claude Code и Codex у Cursor, только под обычным терминалом. Настоящее текстовое поле: мышь, выделение, Enter отправляет, Shift+Enter и Ctrl+Enter — новая строка, Ctrl+V (и Ctrl+Shift+V, Shift+Insert, «Вставить» в меню поля) кладёт картинку из буфера миниатюрой над текстом, скрепка выбирает картинки с диска, файлы, перетащенные на терминал, попадают в поле. При отправке картинки уходят вставкой своих путей (Claude Code и Codex прикладывают такой путь как картинку), затем текст одной вставкой (строки остаются строками одного сообщения), через 250 мс — Enter: Codex в Windows считает Enter сразу после пачки ввода частью этой пачки.
- Пока поле пустое, Enter, стрелки, Tab, Shift+Tab, Esc и Ctrl+C уходят программе — можно отвечать на вопросы агента (доверие к папке, разрешения), не выходя из поля. Esc уходит всегда: он останавливает агента.
- Поле открывается само, когда в терминале запускается агент: раз в 1,2 с Wercode смотрит, какие программы работают под шеллом (`core::process::descendant_names`: снимок процессов в Windows, `ps` в macOS и Linux), и ищет среди них claude, codex (и `codex-<платформа>`), gemini, qwen, aider, opencode, cursor-agent, copilot, goose, crush, amp (`core::agent`). Агенты из npm работают как `node`, поэтому Claude Code узнаётся ещё и по заголовку окна, который он ставит. Пустое поле, открывшееся для агента, закрывается, когда агент выходит; закрытое руками не открывается снова, пока этот агент работает. Переключатель «Поле для запроса агенту» в настройках (`prompt_box`).
- Ctrl+Shift+I (`terminal.prompt_box`, как Ctrl+I у Cursor) и кнопка с роботом на панели вкладок открывают поле под любым терминалом; из поля то же сочетание закрывает его и возвращает клавиатуру в терминал. Библиотека компонентов занимает Ctrl+Shift+I своим инспектором без контекста, а такое сочетание перебивает любое сочетание внутри терминалов, поэтому это сочетание привязано ко всему окну (пустой контекст в `keymap`), а окно передаёт команду терминалам.
- Клавиши поле перехватывает раньше, чем текстовое поле разберёт их по своим сочетаниям (`intercept_keystrokes`); поле лежит рядом с сеткой терминала, а не внутри неё, так что набранное в нём не попадает в шелл само.
- Новое окно (Ctrl+Shift+N, пункт в меню проекта и в палитре) было и раньше, но открывалось во весь экран поверх первого, и казалось, что ничего не произошло. Теперь оно на пятую часть меньше и сдвинуто от центра прежнего — видны оба. В заголовке появилась кнопка «Новое окно».
- Поддержка проекта: адрес USDT (TRC-20) в README и в конце настроек, с кнопкой «Копировать» и предупреждением, что монеты из другой сети пропадут.
- Заодно: картинка из буфера теперь создаётся как новый файл (`create_new`), а не «проверить, что имени нет, и записать» — две вставки в одну миллисекунду (два окна, два терминала) больше не пишут в один файл. Старый тест вставки картинки ждёт, пока путь на экране станет существующим файлом: пока путь рисуется, PowerShell дописывает его серым из истории — путём к картинке прошлого запуска, уже удалённой.

Проверено автотестами (`cargo test`: 85 в ядре, 48 в приложении): поиск программ под процессом на любой глубине, имена агентов, заголовки, расширения картинок; в окне без экрана — Ctrl+Shift+I открывает поле с клавиатурой в нём, Shift+Enter и Ctrl+Enter дают новые строки, Enter отправляет текст в настоящий шелл, Ctrl+Shift+I из поля закрывает его; картинка из буфера показывается в поле и уходит в терминал своим путём; поле открывается для claude и codex, уходит с ними, закрытое руками не возвращается для того же агента.

Проверено в настоящем окне (Windows 11, релизная сборка): `claude` в терминале — поле открылось само с клавиатурой в нём; стрелка вниз и Enter из пустого поля ответили на вопрос о доверии к папке; путь к картинке, вставленный в Claude Code, стал `[Image #1]`, две строки текста одной вставкой — двумя строками одного сообщения без отправки; Esc из поля очистил ввод Claude; `/help`, отправленный из поля, открыл справку; после `/exit` поле закрылось само. `codex` — поле открылось, Enter из пустого поля ответил на вопрос о доверии, `/quit` из поля дошёл (Codex принял его, как только запустил свои MCP-серверы), поле закрылось. ## Всё прямо в терминале, как в Cursor (2026-11-19)

Пользователь не хочет отдельной строки внизу: в Cursor всё делается в самом терминале. Что для этого нужно, проверено на настоящих Claude Code 2.1 и Codex 0.128 под ConPTY (временными тестами в ядре, не в репозитории): Wercode запускал программу так же, как в своём терминале, слал разные варианты «новой строки» и смотрел на экран.

| Что отправлено | Claude Code | Codex | PowerShell |
| --- | --- | --- | --- |
| LF (как было с 2026-11-17) | новая строка | ничего | строка встаёт выше набранной |
| ESC CR (Alt+Enter) | новая строка | ничего | — |
| Shift+Enter нажатием win32 | отправка | новая строка | новая строка |
| Ctrl+Enter нажатием win32 | новая строка | ничего | — |
| Ctrl+J нажатием win32 | новая строка | новая строка | новая строка (`>>`) |

Codex в Windows читает нажатия клавиш, а не байты, поэтому голый LF до него не доходит. ConPTY, запускаясь, сам просит у терминала нажатия клавиш целиком (`ESC[?9001h`, как у Windows Terminal) и понимает их в виде `ESC [ код ; скан-код ; символ ; нажата ; модификаторы ; повтор _`.

- Ядро замечает эту просьбу в выводе (`osc::Win32InputScanner`, `Modes::win32_input`). Пока она в силе, Shift+Enter и Ctrl+Enter в терминале отправляют нажатие и отпускание Ctrl+J; без неё (старая Windows, macOS, Linux) — LF, который там и есть Ctrl+J.
- Картинки в терминале уже работали: Ctrl+V сохраняет скриншот и вставляет путь. Теперь проверено и на Codex — он, как и Claude Code, показывает `[Image #1]`.
- Поле для запроса осталось, но выключено по умолчанию (`prompt_box = false`), кнопка с роботом убрана; открывается Ctrl+Shift+I или из палитры.

Проверено автотестами (`cargo test`: 86 в ядре, 49 в приложении): просьба ConPTY, разбитая на два куска, и её отмена; коды Shift/Ctrl+Enter с ней и без неё; в окне без экрана с настоящим PowerShell — Shift+Enter между `echo one` и `echo two` даёт вторую строку той же команды, ничего не выполнив.

Не проверено руками: Shift+Enter, нажатый на клавиатуре в настоящем окне с Claude Code и Codex (`drive.ps1` не зажимает Shift; сами байты проверены на обеих программах, а то, что окно шлёт их на Shift+Enter, — тестом с PowerShell). При проверке один из вариантов отправил Claude Code команду `! echo one`, и он ответил на её вывод — один короткий запрос к модели.

## Нижняя строка убрана, Shift+Enter при любой раскладке, Cmd+V на Mac (2026-11-19)

- Поле для запроса под терминалом удалено целиком по слову пользователя: всё, что оно давало, работает в самом терминале. Вместе с ним ушли распознавание агентов по процессам для открытия поля, настройка `prompt_box`, Ctrl+Shift+I, кнопка и иконка скрепки, переводы его строк.
- Вчерашний Ctrl+J нажатием оказался зависим от раскладки: при русской раскладке Codex его не видел, а PowerShell вставлял «о» (Ctrl+буква читается через раскладку). Перепроверено при русской раскладке:

| Нажатие win32 | Claude Code | Codex | PowerShell |
| --- | --- | --- | --- |
| Ctrl+J | новая строка | ничего | «о» |
| Alt+Enter | новая строка | ничего | ничего |
| Shift+Enter | отправка | новая строка | новая строка |
| Ctrl+Enter | новая строка | ничего | строка выше |

  Общего ответа нет, поэтому Shift+Enter и Ctrl+Enter теперь смотрят, кто читает клавиши (`process::key_reader`, раз на нажатие: снимок процессов под шеллом, для `node`/`bun` — их командная строка): Claude Code (`claude.exe` или `node …claude-code/cli.js`) получает нажатие Ctrl+Enter, Linux-программы за `wsl.exe` — LF, всё остальное (Codex, PowerShell) — нажатие Shift+Enter, как в Windows Terminal. Enter, в отличие от букв, от раскладки не зависит. Без просьбы ConPTY (macOS, Linux, старая Windows) — LF, то есть Ctrl+J, на котором Claude Code и Codex там начинают новую строку.
- macOS: Cmd+V в терминале печатал букву «v», Cmd+C не копировал. Теперь Cmd+C копирует выделенное, Cmd+V вставляет (скриншот — путём, для агента), остальные Cmd-сочетания в шелл не попадают. Простой Ctrl+V на macOS и Linux уходит программе: Claude Code и Codex сами берут картинку из буфера.

Проверено автотестами (`cargo test`: 84 в ядре, 48 в приложении): выбор читателя клавиш по списку процессов и командной строке, чтение командной строки настоящего процесса, коды новой строки для каждого читателя; в окне без экрана с настоящим PowerShell при русской раскладке — Shift+Enter даёт вторую строку той же команды; Cmd+V вставляет, Cmd+K ничего не печатает.

Проверено на настоящих программах (временными тестами, при русской раскладке): из PowerShell запущен `claude` — распознан как Claude Code, новая строка встала; запущен `codex` — распознан как консольная программа, Shift+Enter дал вторую строку, `/quit` закрыл его. Во время проверки очистка ввода Claude двумя Esc не сработала, и вместе с `/exit` ушло сообщение — ещё один короткий запрос к модели.

Не проверено руками: Shift+Enter с клавиатуры в настоящем окне при русской раскладке (байты и выбор проверены на программах), Claude Code из npm (только тестом выбора), macOS и Linux вживую. Заметка: в Windows PowerShell 5.1 при русской раскладке Ctrl+C вставляет «с» вместо прерывания — так его старый PSReadLine читает Ctrl+буквы; способ отправки на это не влияет.

## Все изменения одним списком (2026-11-20)

Идея из Zed (multibuffer): агент поработал — всё, что он поменял, читается и разбирается в одной вкладке.

- Вкладка «Все изменения»: Ctrl+Shift+A, команда «Git: показать все изменения» в палитре или кнопка в заголовке «Изменения» и «Изменения в индексе» git-панели. Изменённые файлы идут подряд с подсветкой синтаксиса; новые файлы — целиком как добавленные (не больше 500, файлы больше 1 МБ — только именем); файлы с конфликтом слияния не показываются, а считаются в заметке под панелью.
- Сверху переключатель «Не в индексе / В индексе», число файлов и строк, «Добавить всё в индекс» («Убрать всё из индекса»). Под каждым куском — «Добавить в индекс» и «Отменить изменения» (для нового файла — «Переместить в корзину»), среди изменений в индексе — «Убрать из индекса». У файла в заголовке — открыть, отменить, добавить (убрать).
- Отменённое возвращается кнопкой «Вернуть»: кусок или файл накладывается обратно, новый файл записывается из памяти (в корзине он тоже есть). Файл без строк (двоичный) отменяется только после вопроса.
- После кнопки список встаёт на следующий кусок, а не прыгает наверх. Изменения на диске подхватываются сами; если ничего не поменялось, список остаётся на месте, а если поменялось — возвращается к куску, который был виден. Двойной щелчок по строке открывает файл на ней.
- Ядро: `core::changes` читает `git diff` (и `--cached`) с принудительными префиксами, без внешних программ, textconv и переименований, режет на файлы и куски и кладёт один кусок в индекс, убирает или отменяет через `git apply`. Окно: `changes.rs` на компоненте `Diff` из библиотеки (заголовки файлов и аннотации под последней строкой каждого куска).
- Сборка из исходников не обновляется сама; теперь рядом с этой надписью в настройках есть кнопка «Скачать установщик» со ссылкой на выпуски.

Проверено автотестами (`cargo test`: 87 в ядре, 49 в приложении): разбор патча (два куска, имя с пробелом, удалённый, двоичный файл, смена прав, кавычки в имени, конфликт), новый файл как патч git; на настоящем репозитории (с `core.autocrlf=true`) — кусок в индекс и обратно, отмена и «Вернуть», файл целиком, отказ при изменившемся файле, репозиторий без коммитов; в окне без экрана — Ctrl+Shift+A, кнопки под кусками, «Вернуть», переключение сторон, «Добавить всё».

Проверено в настоящем окне на демо-репозитории: вкладка, кусок в индекс (список встал на следующий кусок), новый файл в корзину и обратно, сторона «В индексе», кнопка установщика в настройках.

## Конфликты кнопками, редактор сочетаний, worktree, сплиты редактора, автоустановка серверов (2026-11-20)

- Конфликты слияния: файлы, которые git не смог слить, стоят первыми во вкладке «Все изменения», над каждым конфликтом кнопки компонента `Diff` «Принять текущее / входящее / оба». Выбор сразу переписывает этот конфликт в файле (`core::changes::resolve_conflict`, свой разбор меток, с частью предка diff3). Последний выбор добавляет файл в индекс; «Вернуть» делает его снова неслитым (`git update-index --unresolve`) и возвращает текст. Файл, где метки убраны руками, получает кнопку «Отметить решённым». Щелчок по такому файлу в git-панели и по «N конфликтов» в строке состояния открывает список на нём.
- Редактор сочетаний на экране настроек: у каждой команды имя как в палитре и кнопка с сочетанием; щелчок — и следующее нажатие становится сочетанием. Нажатия перехватываются до команд (`intercept_keystrokes`), Esc отменяет. Буква без Ctrl/Alt отклоняется (кроме F1–F24), занятое сочетание называется, Ctrl+буква предупреждает, что терминал её больше не получит. «Убрать» и «Вернуть встроенное», поле поиска. В `settings.toml` пишется только строка этой команды в `[keys]` (`config::save_keys`).
- Worktree: кнопка рядом с веткой и команда палитры показывают папки репозитория; щелчок переключает окно, отдельная кнопка открывает в новом окне, имя ветки создаёт worktree рядом с проектом (`git::worktree_folder`, `add_worktree`). Удаление — для папок без изменений; папка, удалённая руками, просто забывается (`git worktree prune`).
- Сплиты редактора: во вкладке файла может стоять второй файл справа или снизу, с перетаскиваемой линией. Кнопки на панели файла и палитра открывают «Перейти к файлу» для второго файла, в дереве есть «Открыть сбоку», вкладку можно бросить на редактор. В раскладке одной строкой Ctrl+Shift+D/E в файле делают то же; в раскладке «терминал снизу» эти клавиши, как и раньше, делят терминал. Ctrl+Shift+W закрывает файл с клавиатурой. Пара сохраняется в `state.json` (`TabLayout::File { beside }`; старые версии это поле пропускают).
- Автоустановка языковых серверов (`core::lsp::download`): «Установить» в строке состояния скачивает сервер в папку Wercode — rust-analyzer, clangd, ruff, taplo с GitHub, серверы на Node.js через npm и собственный Node.js (проверка по SHASUMS256.txt с nodejs.org). Сервер собирается в соседней папке и переносится целиком; рядом лежит `server.json` с тем, как его запускать. Сервер, найденный на компьютере, по-прежнему важнее. Распаковка: zip — крейтом `zip`, одиночный `.gz` — `flate2`, `.tar.gz` — системным `tar`.
- Попутно: тесты `term/area.rs` разрешают «парковку» потоков (шеллы), из-за чего один из них изредка падал.

Проверено автотестами (`cargo test`: 98 в ядре, 57 в приложении): разбор и замена конфликтов, решение и возврат на настоящем репозитории; запись `[keys]`; запись нажатия в сочетание; worktree на настоящем репозитории (создание, вторая папка, удаление, забытая папка); сплиты (перенос, замена, закрытие половины, перетаскивание вкладки, восстановление); распаковка zip и gz, поиск программы, перенос папки сервера; в окне без экрана — все кнопки выше.

Проверено в настоящем окне: конфликт с двумя местами — «Принять входящее», затем «Принять оба», файл ушёл в индекс; список worktree; список сочетаний и режим записи с отменой; два файла в одной вкладке и их восстановление после перезапуска.

Не проверено: настоящие скачивания серверов — запуск сетевого теста из сессии заблокировала система безопасности; его можно запустить руками: `cargo test -p wercode-core -- --ignored real_downloads --nocapture`.

## Переключатель вкладок, режим «дзен», обновление серверов, PATH на macOS, панель «Проблемы», Linux (2026-11-21)

- Ctrl+Tab — переключатель вкладок со списком (идея из Zed): вкладки в порядке последнего использования, выделена предыдущая. Отпустил Ctrl — открылась она; ещё нажатия с зажатым Ctrl идут вниз по списку, Ctrl+Shift+Tab — снизу вверх; короткое нажатие возвращает на вкладку, где был до этого. Из палитры («View: Switch Tab») список ждёт стрелок и Enter или щелчка, Esc закрывает. У файла показана его папка, у терминала — папка, где он стоит. Ctrl+PageDown/PageUp по-прежнему идут по ряду. Если Ctrl отпущен раньше, чем список нарисован (быстрое нажатие), его отпускание замечается при первой отрисовке. Сочетания — `terminal.switch_tab` и `terminal.switch_tab_back`; держимой считается та клавиша, с которой открыли (если сочетание переназначено на Alt).
- Режим «дзен» (Ctrl+Shift+Z, «View: Zen Mode»): окно на весь экран, без заголовка, боковой панели и строки состояния; подсказка, как выйти, исчезает через 4 с. Те же клавиши возвращают окно как было; просьба показать боковую панель тоже выводит из режима. Ctrl+Shift+Z свободна и в редакторе: «повторить» там Ctrl+Y.
- Скачанные языковые серверы обновляются (`download::update_all`): раз в сутки каждый, через 30 с после запуска и потом каждые 6 часов, если включено автообновление. Каждая версия лежит в своей папке внутри папки сервера, `server.json` называет текущую и помнит версию (тег релиза GitHub, версии пакетов npm, версия Node.js) и время проверки. Новая версия кладётся рядом со старой, которую может держать работающий сервер; ненужные папки удаляются при следующем запуске Wercode (`download::prune`), до старта серверов. Серверы на npm при обновлении Node.js переводятся на новый. Серверы, скачанные 0.6 (файлы прямо в папке сервера, без версии), обновятся один раз, и их старые файлы уберутся.
- На macOS при запуске из Dock (и на Linux из меню) у окна только системный `PATH`: Wercode один раз спрашивает login-шелл (`$SHELL -l -i -c`, с метками вокруг ответа и пределом 5 с) и ищет серверы и в его папках (`environment::login_path`). Добавлены папки nvm (новейшая версия Node.js первой), Volta и Bun.
- Панель «Проблемы»: сообщение получает место первым, источник («rustc(unused_variables)») сжимается до нуля раньше, чем обрежется сообщение, место «строка:колонка» всегда целое. Подсказка строки показывает сообщение целиком с источником. Подсказку GPUI меряет до того, как у неё есть ширина: текст, переносящийся внутри одного элемента, и переводы строк внутри одного текста наезжали на строки ниже, поэтому каждая строка — свой элемент, а у длинного сообщения своя ширина.
- `tools/drive.ps1` умеет держать клавиши: `down:17; key:9; up:17` — Ctrl+Tab с зажатым Ctrl. Состояние клавиш ставится потоку окна через `AttachThreadInput` и `SetKeyboardState`, потоки связаны до конца сценария (отвязанный поток возвращается к своему состоянию раньше, чем прочтёт клавишу). Фокус и другие окна не трогаются.
- Linux проверен руками впервые: архив 0.6.0 из релиза в Ubuntu 24.04 под WSLg. В чистой системе нет `libxkbcommon-x11-0` и `libxcb-xkb1`, без них Wercode не запускается; `install.sh` теперь называет недостающие библиотеки и команду `apt`, README тоже. С ними: окно, дерево с git-буквами, bash с цветным приглашением, кириллица в терминале, редактор с подсветкой, git-панель, строка состояния; «Install» скачал rust-analyzer (одиночный `.gz`) и тот заработал (крошки, значок в строке состояния).

Проверено автотестами (`cargo test`: 104 в ядре, 63 в приложении): порядок списка вкладок; быстрое нажатие, удержание, обратный ход, отпускание до отрисовки, Enter/Esc/стрелки, щелчок; «дзен» (заголовок, панель и строка состояния скрыты, подсказка уходит, выход, панель выводит из режима, терминальные клавиши работают); обновление серверов (не пора — не спрашивает; та же версия — только время; новая версия рядом со старой; ошибка сети ничего не меняет; очистка при запуске; серверы 0.6; переезд на новый Node.js; испорченный `server.json` не трогается); путь из ответа login-шелла; порядок версий nvm.
